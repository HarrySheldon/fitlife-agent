## 1. 问题与已确认选择

已通过源码和合成验证确认：快捷动作将英文模板传给 Writer，但 Writer 要求忽略界面语言；证据渲染标签又写死中文。普通回答缺少按动作设计的长度／内容契约。当前 CoachDrawer 桌面端靠右、最大420px、遮罩阻断页面；CoachPanel 只保存单个回答、没有追问输入，关闭后卸载清空结果。部分入口要重复点击，计划解释与调整生成的命名混淆。独立 Chat 页面未被正式路由使用，不能把现有前端消息数组当作已经支持多轮上下文。

用户已确认：

1. 一个教练 Agent，支持多条聊天；同一聊天可以跨饮食、训练、计划等话题，不按页面强制分聊天。
2. 全局悬浮入口，点击展开教练窗口，可收起。
3. 收起或切换聊天不取消已接受任务；完成后提示，不自动弹出打断用户。
4. 明确的停止按钮；同一账户同一时间只运行一个教练请求，其他聊天可阅读／编辑输入，不允许静默排队。
5. 聊天属于账户历史，支持恢复、删除和导出。不同聊天不共享正文或长期记忆；均可按需读取正式档案和业务记录。
6. 历史上限90天，按每条消息的服务端发送时间计算，不以聊天活跃来延长旧消息，不保留过期内容的隐藏摘要。

## 3. 总体结构与职责

沿用现有 AgentRuntime、安全系统、数据读取工具、结构化网关及确定性写入流程。新增窄的教练会话模块，负责 conversation/turn 的持久化、输入上下文组装和活动请求协调；不得再创建第二套宽松 Agent 执行链路。

- **Conversation**：一条聊天的身份、标题、所属用户和消息集合，不等同于一次 Runtime run。
- **Turn**：一次明确发送或点击快捷动作产生的请求，包含用户消息、动作、显式业务上下文引用、语言／输出契约快照、结果和状态。
- **Run**：该 Turn 关联的一次 Runtime 执行，沿用 run_id/request_id、期限、预算、安全步骤和审计。
- **展示历史**：90天内合法保留的消息，供用户查阅。
- **模型上下文**：当前聊天中必要的近期消息投影、当前问题和本次按需读取的数据；不是展示历史的直接复制。

前端悬浮窗和展开后的完整视图共用同一个会话控制器，不分别发请求或保存两份聊天。业务页面只传可信的上下文引用及动作，模型不得自行指定其他账户、任意文件或查询路径。

## 4. 窗口、导航与输入

### 4.1 悬浮入口

登录后的业务页面统一显示带文字可访问名称的「教练」入口，默认在右下角，避开移动端安全区域及页面固定按钮。登录、账户删除确认等敏感流程不覆盖主要操作。入口有 idle/running/unread/error 状态，不能只用颜色区分，也不显示健康内容摘要。

点击入口恢复最近打开的聊天，不触发模型。首次无历史时显示空会话与示例问题；首次发送才创建正式 Conversation。所有模型请求必须来自用户明确发送或动作点击。

### 4.2 展开窗口

桌面默认居中宽窗口，建议宽720px、最大高度80vh，并受视口边距约束；可通过标题栏拖动，拖动范围限制在视口内。提供收起、最大化与历史入口，不新开浏览器窗口。最大化使用应用内完整教练视图，保持同一会话、消息位置和未发送输入。

背景页面可以继续操作，因此使用非模态 dialog，不保留目前遮罩＋aria-modal=true＋焦点陷阱的组合。打开后焦点进入标题或输入框，关闭／收起恢复到入口；只有独立的危险操作确认对话框使用真正模态及焦点限制。Esc 收起，不停止任务、不删除消息。窗口大小变化后保持在可见区域内，移动端直接采用全屏。

顶部包含教练、聊天标题、当前运行状态；中间为消息列表；底部固定多行输入和发送／停止按钮。历史切换、新建、重命名、删除可在内部列表完成，不强制把业务页面挤窄。窗口位置不携带聊天内容，不将正文保存到 localStorage/sessionStorage。

### 4.3 输入和阅读

桌面 Enter 发送、Shift+Enter 换行；中文输入法组合期间 Enter 不触发发送。移动端提供独立发送按钮。输入框有可访问名称、长度提示和键盘说明。每条聊天的未发送草稿在当前前端会话内独立保留，不因收起或切换丢失，不默认持久化浏览器明文草稿。

消息列表只在用户位于底部时跟随新消息；用户向上阅读时不强制拉回，显示「有新回复／回到底部」。失败消息保留输入并提供显式重试；错误码与 request_id 折叠，默认给出可操作提示，不展示供应商原始正文。

## 5. 多聊天与页面上下文

默认恢复用户最近选择的聊天。用户主动新建／切换／重命名／删除，不因页面切换自动新建或重置。

自由输入默认不附加当前页面快照：模型按问题需要，通过已有授权数据读取能力获取必要资料。页面导航本身不改变当前对话指代。

点击「解释今天／解释周报／解释当前计划／询问目标建议」时，立即展开并在当前聊天追加一条用户可读的动作消息，再发起任务，不要求重复点击。请求附带明确的 context_ref，例如日期、plan_id、report_week，界面展示对应上下文标签。它是本次 Turn 的上下文，不是无限期生效的隐式指令。

计划／报告读取已保存对象，不擅自重新生成替代品。缺少对应对象时先提示用户选择，不猜测。来源显示数据日期／读取时间；记录变更后旧答案标记为历史分析，不被静默改写。新请求读取最新资料，旧消息和其中的模型推断不能覆盖正式数据。

动作明确区分：

- 解释当前计划：只读解释。
- 生成调整草稿：产生候选，不激活。
- 确认应用：确定性业务操作，必须独立确认，不能从聊天文本直接执行。

## 6. 会话历史不等于模型记忆

模型输入只来自当前用户当前聊天的未过期内容；不得读取其他聊天正文。用户正式档案与正式业务记录按既有权限和最小输入投影读取，不把跨聊天模型推断变成资料。

首版保留近期完整回合，历史上下文同时受轮数和当前 Runtime 字符／Token预算约束；建议上限为最近6个已完成回合，实际更低预算优先。不得将剩余预算全部耗在历史而挤掉当前问题、安全指令和必要证据。超出部分不发送，不能拼接半条消息冒充完整语义；界面提示只参考近期对话，必要时询问用户澄清。

不自动生成长期摘要，不新增跨聊天记忆表。用户明确提及某个旧资料时，读取正式记录而不是把模型历史回答当作事实。会话标题由用户设置或本地基于首条问题生成，不额外调用模型，不将正文写入 URL、通知或日志。

## 7. 语言和回答契约

语言优先级：用户本次明确请求的回答语言 > 本次开始时的账户语言设置 > 应用默认语言。内部英文动作模板不参与用户语言推断。自由提问没有明确指定时也沿用设置，不因偶尔出现英文模型名而切换。历史回答不自动翻译；修改语言只影响后续 Turn。

语言／动作／输出契约作为系统侧受控元数据一路传到生成与确定性渲染，必须经过输入投影允许列表，不能靠任意 user text 伪装。证据标签、空状态、错误和安全提示同样按已选语言渲染，修复目前固定中文标签。

### 7.1 快捷动作

统一结果为 summary、有限 findings、next_step、evidence_refs 及必要的系统安全提示；每类动作有自己的字段规则，不返回无限 Markdown 长文。

| 动作 | 默认可见内容 | 展开内容 |
| --- | --- | --- |
| 解释今天 | 一句话结论、最多3项关键情况、1个下一步 | 已有证据、数据日期、缺失项 |
| 目标建议 | 确定性服务给出的建议值／范围、简短依据、待确认事项 | 计算依据与限制，不自动修改目标 |
| 下一餐建议 | 最多3个候选、简短理由及必要饮食限制 | 已有来源与替换说明 |
| 今日训练建议 | 最多3个调整点、原因、必要注意事项 | 所依据的计划和记录 |
| 周报／计划解释 | 核心变化、优先问题、下一步 | 来源和详细依据 |

建议初始契约：summary 最多120个Unicode字符；findings 最多3条、每条120字符；next_step 最多120字符。数字来自确定性结果／证据引用，不要求模型猜测。超过限制不直接发布原文，也不直接字符串裁剪后当成功。

### 7.2 自由提问和详情

默认简短回答，建议正文最多1200个Unicode字符，按问题选择简短段落或列表，不强制所有交流都长得像同一张卡片。用户明确要求详细说明时使用独立的较大但有界额度，建议最多3000字符；实际值仍受整次预算限制。特殊的安全拒绝和紧急引导使用专用受控模板，不因一般长度限制被裁掉。

展开已保存的证据不额外请求模型。「详细解释／继续追问」是明确的新请求，进入同一聊天并显示加载与费用提示，不偷偷先生成完整长文藏起来。未来数值可通过验收调整，但不能只留下“简洁一点”的提示词。

生成前应用动作级输出Token额度，协议层映射供应商参数；生成后校验字段、长度、证据和安全。格式失败可使用当前任务既有修订预算，不能新增无限循环或重置整任务额度；没有剩余额度则显示明确失败／可重试，不把未校验内容作为降级答案。

## 8. 执行状态、进度和取消

前端窗口生命周期与后端任务生命周期分离。新 Turn 通过短请求接受，返回 turn_id；服务端立即尝试运行，不建设积压任务队列。窗口可查询真实状态，重新打开／刷新可恢复已保存结果及仍在运行的状态，不因为 HTTP等待断开就丢失任务身份。

对外阶段来自实际事件：读取必要资料、分析、组织回答、安全检查；没有执行的阶段不展示，不伪造百分比。首版不流式公开未审查答案，不显示内部推理。安全审核通过后才原子发布正式结果；失败／取消／超时不得把部分草稿写成成功回复。

状态包含 running、cancellation_requested/stopping、succeeded、failed、cancelled、timed_out、interrupted。一个账户只允许一个活动请求，活动范围包含正在停止或清理的任务。多标签页必须经过同一个服务端原子准入，前端禁止发送只是辅助。冲突返回当前有权查看的活动 Turn 信息，提供「前往该聊天」和「停止」，不自动排队。

同一发送动作使用幂等请求标识，双击／网络重传不能重复创建消息和计费请求。失败后的主动重试是新尝试，明确费用并保留旧失败记录；正式数据写入仍由各业务幂等命令控制。

### 8.1 取消必须处理传输，不只是隐藏状态

现有 Runtime 有协作式取消，但同步工作线程不能被强杀，取消后的上游调用可能仍在返回。因此不能仅接一个停止按钮就宣称执行已经停止。

本轮 Coach 模型调用须接入可取消的异步HTTP传输 Adapter，取消信号覆盖 Planner、Writer、结构化生成、安全审核与重试等待；请求构造和本地校验尽量复用 M 阶段已有实现，不另造宽松载荷。取消时关闭当前传输并等待清理，在此之前显示「正在停止」且不释放账户活动槽。所有后续步骤必须检查取消；迟到结果不能入库、不能触发业务操作。无法确认传输已结束时，不显示“已停止”或开放新的模型请求。

用户侧取消不保证上游服务商撤销已经开始的计算或费用，必须如实说明。整体期限仍取当前 Runtime 策略；任何延长均不能来自客户端的任意参数。

后台运行仅指当前应用服务进程内继续，不能宣传为任务队列或进程重启后自动续跑。服务重启时把无法恢复的活动 Turn 标记 interrupted，保留用户输入供明确重试，不自动重发模型。窗口收起／路由切换只是收起；账户退出或撤销认证应停止该账户活动任务，其他账户不能承接结果。

## 9. 存储、90天保留与账户生命周期

聊天数据存入现有业务 SQLite 的独立表，经 Repository 接口访问，采用版本化迁移，不再创建第三个独立数据库。保留现有 runtime 库记录运行审计；正文不复制到 run日志中。Conversation、Turn、Message、活动准入记录均有明确 user_id/owner 条件和外键。

每条消息使用服务端 UTC created_at，年龄达到90天即不可展示、导出、搜索或作为模型上下文。用户消息过期时，对应回复及派生上下文也一并失效，避免保留无来源的孤立回复；这只会更早清除该回合的派生内容，不会延长任一消息。若会话已无保留消息，移除该会话及标题，避免敏感标题孤立保留。将来新增摘要也不得绕过同一到期规则。

读路径必须实时过滤期限，不依赖清理任务正好运行。物理清理在启动和受限维护批次中执行，重复执行幂等；应用未运行时不承诺到秒删除，启动后再清理。SQLite删除不等于法证级安全擦除；用户自行保留的数据库备份、下载的导出文件不会被应用自动收回或删除，不能作不实承诺。

支持单条聊天删除、清空历史、账户导出／删除。删除活动聊天需明确确认「停止并删除」：先设置不可恢复的删除标记、阻止迟到结果重新创建，再停止任务并清理。账户删除沿用既有生命周期保护，撤销认证并清理聊天与运行中引用；不会删除正式饮食／训练数据，除非执行的是用户明确确认的整个账户删除。

仅持久化用户已提交消息、通过审核的回答、有限来源引用和必要运行状态；输入中的敏感内容按现有规则处理。所有查询、取消、更新、导出和活动状态访问都校验所属用户。正文不进入普通日志、错误堆栈展示、通知、指标标签或第三方遥测。导出继承现有快照和大小预算，不因聊天量大失去限制。

在实际创建开发分支／工作树、集成或正式迁移前，必须按 AGENTS.md 对保留的主业务库及需要保留的 runtime库做备份／完整性校验，并在副本验证迁移。本文不授权绕过备份。

## 10. 其他交互统一规则

- 确定的快捷动作一次点击执行；通用悬浮入口只恢复，不收费。
- 生成时不清空上一条回答，失败仍保留已有结果及输入。
- 错误显示在对应消息旁，包含重试或去设置等可执行路径；安全拒绝不提供绕过安全的重试诱导。
- 默认展示数据来源、日期和是否建议，技术trace折叠，聊天不显示冗长工具英文名清单。
- 收起保留输入／滚动位置；有新结果只提示，不抢焦点。
- 会话切换对正在编辑的业务表单无副作用，悬浮窗不自动提交或重置页面。
- 删除、清空、停止和应用正式业务变更使用不同文案，不能复用一个含糊的“确认”。
- 桌面和手机均验证键盘、输入法、屏幕阅读器提示、375/768/1024/1440宽度、缩放及可达触摸目标。

## 11. 验收要求

1. zh/en界面下，所有快捷动作、自由提问、证据渲染、拒绝与空状态语言一致；明确语言请求可覆盖本次，不改变账户设置。
2. 模型产生超长、错字段、虚构数值或危险内容时均不会发布未审核草稿；长度和条数测试使用确定性合成网关，不能用前端隐藏代替后端限制。
3. 收起、展开、最大化、路由切换、刷新不重复调用模型；关闭后恢复同一聊天和已保存消息，日期／计划上下文不串线。
4. 多聊天之间正文不串读；多标签页并发发送只有一次准入成功，重复请求不重复计费，停止期间不得启动第二个请求。
5. 取消覆盖真实可取消的合成慢HTTP、等待与审核，观察到传输资源结束才释放槽；迟到响应不可发布；服务重启不自动重发。
6. 90天边界、UTC／本地时间、后台未清理、孤立派生内容、删除中迟到结果、导出大小和账户删除均有数据库集成测试。
7. 对话建议不直接写目标或激活计划；正式写入继续要求业务确认、所有权和幂等校验。
8. 完成前进行浏览器层键盘／输入法／多窗口状态／响应式检查，而不仅是组件Mock测试。真实模型验收须另行明确授权和预算，不从本设计确认推断可使用密钥。

## 12. 建议实施顺序与不宣称范围

本体验改造作为 C 阶段并入原主计划，在模型连接M之后、S3之前处理，不改写S0–S5编号或声称S3已完成。统一顺序为M → C0–C4离线 → S3 → S4 → S5；C4中的真实模型与发布部分只在S5统一执行。聊天中的S3任务仍由原S3服务管理范围、预算与确认，聊天不是第二个计划生成器。整体先统一设计，再分纵向检查点实施：

1. C0：语言与动作回答契约，修复快捷动作语义和数值／安全渲染，不先搭一个空聊天壳。
2. C1：账户会话、90天访问／清理规则、上下文投影、导出删除与迁移副本验收。
3. C2：Turn接受／状态／原子准入、可取消传输和终态发布；此步完成前不交付虚假的后台继续或停止按钮。
4. C3：全局悬浮窗、统一多聊天控制器、完整视图、页面快捷入口和可访问性。
5. C4：离线整体验收、回归、安全和隐私检查；真实模型测试与部署并入后续S5，按对应授权执行。

不引入无限自主循环、跨聊天记忆、会话树、任务积压队列、后台定时主动健康建议、未经审核的文本流、模型直接写正式数据或进程重启自动续跑。不把更短回答当作已经测得的性能提升；后续仅用同等安全条件下的实测首结果时间、输出量和费用作对照。
