## 已实现

- Layout 持有 owner 隔离的统一控制器；居中非模态浮窗、桌面拖动、最大化和手机全屏共用执行身份。收起不会取消，也不会重复生成；后台完成只提示新回复。
- 多聊天切换、改名和删除确认；草稿只在内存中按聊天隔离。sessionStorage 仅保留 owner 对应的聊天 ID，不保存正文或草稿。刷新只读恢复状态，不重发模型请求。
- Today/Profile/计划/周报使用同一入口。计划和周报传递持久对象引用，由后端按 owner 重新读取；缺失对象拒绝，不偷偷重新生成。正式业务表单与确认入口不变。
- 同聊天上下文只选未过期、审核成功的完整回合，最多六轮，并受本次剩余预算约束；Planner/Writer 获得清洗后的 role/body，不获得授权标记。历史回答不是事实来源。
- “为什么／再详细一点”等封闭追问可沿用服务端保存的动作、日期及对象引用；新业务目标不继承许可。模型输出预算贯穿保存对象解释路径，发布前再次校验正文上限，超限拒绝，不截断发布。
- 回答默认展示来源标题、日期/对象引用及建议标识，技术信息折叠，Markdown 不执行原始 HTML。来源不暴露原始检索正文或任意 trace。
- 失败状态支持显式重试，并提示新请求可能产生费用；只逐项重建请求白名单。按聊天保存最新状态，后台 A 完成不会覆盖 B 的失败重试入口。
- 显式退出登录、成功改密和撤销其他会话都接入同一取消服务。退出接口负责取消当前账号运行，并非 JWT 全局撤销接口；离线时客户端无法保证立即送达，仍依赖服务端期限。

### 验收中发现并修复

1. **停止提示跨回合残留**：取消返回的计费提示只写不读，切聊天或发下一条后仍显示。先补失败用例
   （`useCoach` 新测试断言第二次发送与切换聊天后为空），再在新回合开始和会话切换时清空；
   组件、hook 与浏览器三层复验。
2. **200% 缩放下欢迎页贴底**：空会话默认滚到底部，512×450 CSS 视口下欢迎标题被裁。空会话改为从顶部开始。
3. **全量前端唯一失败是夹具**：jsdom 的 Blob 无 `stream()`，且 `Response.blob()` 返回 Node Blob，
   与 `expect.any(Blob)` 不同源。改为只实现被测代码所需成员的响应替身，断言未变，产品代码未动。
